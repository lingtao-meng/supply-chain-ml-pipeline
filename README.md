# 供应链延迟交付风险预测

[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](https://opensource.org/licenses/MIT) [![Python](https://img.shields.io/badge/python-3.10%2B-blue.svg)](https://www.python.org/)


用 DataCo 全球供应链数据（180K+ 条订单）做延迟交付预测。核心不是「预测会不会延迟」，而是**预测延迟几天，再按统一的成本函数决定给谁加急**。

**最重要的结论不是一个省了多少钱的数字，而是「这套方法什么时候值得」：**

> 在统一成本口径下，不做任何干预要花 **$4.88M**，全量加急 **$3.35M**，分位阈值策略 **$3.26M**，事后最优上界 $2.12M。
> 分位规则相对传统二分类的收益**高度依赖「加急成本 / 日罚金」的比值**：当加急 $100、罚金 $100/天时降本 **34%**；当加急只要 $50 而罚金 $200/天时，两者只差 **1.7%**——因为那时候「全都加急」本来就接近最优。
> 所以正确的说法是：**当干预贵、延迟代价高时，分位决策才值得做**；而不是「分位数回归一定比二分类好」。

---

## 业务问题

订单延迟交付是供应链里代价很高的风险。业务上真正要回答的不是「这单会不会延迟」，而是：

1. 会晚几天？（点估计不够，需要分布）
2. 值不值得花钱干预？（加急成本 vs 延迟罚金）
3. 只能加急一部分订单时，先加急哪些？（产能约束下的排序）

---

## 数据

DataCo Supply Chain Dataset（Kaggle 公开数据）。180,519 条订单，53 个原始字段，时间跨度 2015-01-01 → 2018-01-31。

- 延迟率 **54.7%**，平均延迟 0.54 天，累计延迟 16.3 万天
- 有缺失值也有异常值，接近真实场景

---

## 做了什么

1. **目标构造**：`delay_days = 实际运输天数 − 承诺运输天数`。注意 `Days for shipping (real)`、`Delivery status` 这类字段**事后才知道**，全部排除在特征之外
2. **特征工程**：只保留下单时可得的信息——日期派生（月/周/季/是否周末/年内第几天）、金额类（总价、折扣金额、单位运输天价值）、交互项（数量×运输天、折扣×金额），类别字段编码，共 18 维
3. **时间切分**：按订单日期排序后 70/15/15，训练用过去、测试用未来（不是随机切分）
4. **分位数回归**：用 `GradientBoostingRegressor(loss="quantile")` 分别拟合 P10 / P50 / P90，得到延迟天数的分布估计
5. **统一成本决策**（本项目的关键改动，见下节）
6. **诊断链**：对抗验证 → 分段评估 → SHAP → AutoML 天花板测试，回答「这个 AUC 为什么上不去」

---

## 关键改动：把所有策略放到同一个成本函数下

早期版本犯了一个很典型的错：**每个策略用不同的公式算成本**。「不干预」的基线当时只按预测延迟折算，结果算出来比模型还便宜（$242K vs $509K）——这显然荒谬，但也最容易被一句话问穿。

现在所有策略统一用：

```
单笔成本 = 动作成本 + 日罚金 × 动作后的剩余延迟天数
动作：不加急($0) / 提前通知($20，罚金打 6 折) / 加急($100，减 2 天)
日罚金 = $200/天
```

在 27,078 条测试订单上、同一次时间切分下：

| 策略 | 总成本 | 单均成本 | 干预率 | 抓到延迟的比例 | 干预命中率 |
|---|---|---|---|---|---|
| 事后最优（upper bound） | $2,120,100 | $78.30 | 54.7% | 100% | 100% |
| **分位阈值（本项目）** | **$3,258,160** | **$120.32** | 99.8% | 99.9% | 54.7% |
| 全量加急 | $3,346,800 | $123.60 | 100% | 100% | 54.7% |
| 二分类（p50>0 就加急） | $3,358,100 | $124.02 | 98.1% | 98.6% | 55.0% |
| 产能约束 25%（按期望收益排序） | $3,880,520 | $143.31 | 25.0% | 32.9% | **71.9%** |
| 不做干预 | $4,882,200 | $180.30 | 0% | 0% | — |

> 复现：`python scripts/refresh_cost_analysis.py`，输出在 `results/`。

### 「模型值不值得」的参数边界

固定 $200/天罚金时，分位规则的干预率是 99.8%——意思是**这个成本结构下「几乎全都要加急」**，模型的边际价值只有 3%。把两个参数一起扫，结论完全不同：

| 日罚金 | 加急成本 | 二分类成本 | 分位规则成本 | 降本 |
|---|---|---|---|---|
| $100/天 | $50 | $1,679,050 | $1,601,440 | +4.6% |
| $100/天 | $100 | $3,006,900 | $1,977,220 | **+34.2%** |
| $100/天 | $150 | $4,334,750 | $1,977,220 | **+54.4%** |
| $200/天 | $50 | $2,030,250 | $1,995,200 | +1.7% |
| $300/天 | $125 | $4,373,225 | $4,523,710 | **−3.4%** |

最后一行是关键：**存在参数区间，分位规则反而不如二分类**。这说明决策规则的收益不是由模型精度决定的，而是由成本结构决定的——这条结论比任何一个单一数字都更有用。

### 产能约束下的排序

现实中不可能给所有订单加急。按期望收益排序、只加急前 k%：

| 可加急比例 | 总成本 | 干预命中率 | 抓到延迟比例 |
|---|---|---|---|
| 10% | $4,390,800 | 80.3% | 14.7% |
| 25% | $3,880,520 | 71.9% | 32.9% |
| 50% | $3,692,700 | 55.8% | 51.0% |
| 100% | $3,258,160 | 54.7% | 99.9% |

产能收紧时，命中率从 54.7% 升到 80.3%——**排序模型的价值在产能受限时才真正体现出来**。

## 模型本身的表现

| 指标 | 数值 |
|---|---|
| 二分类基线（XGBoost，时间切分）AUC | **0.7794** |
| P50 模型 MAE | **0.959 天** |
| P10 / P50 / P90 分位覆盖率 | 12.2% / 64.5% / 93.8% |

> **分位覆盖率偏高是已知问题**：名义 10% / 50% / 90%，实测 12.2% / 64.5% / 93.8%，说明预测整体偏保守（高估延迟）。下一步用保形预测（conformal）做校准，而不是继续调模型。

---

## 为什么 AUC 只有 0.78

这个数字看起来不高，但背后是一条完整的诊断链：

**第一层：是不是数据清洗出问题了？**
不是。从只删 PII 到删光所有可能泄露的特征，非泄露特征的 AUC 全部落在 0.72–0.73 之间，差距不到 0.01。

**第二层：是不是特征工程不够？**
不是。时间特征、业务特征、交互特征从 17 列扩到 44 列，所有特征工程的 AUC 提升加起来不到 0.01。最强单特征的互信息只有 0.13。

**第三层：是不是时间漂移？**
是的。对抗验证证明训练集和测试集分布严重不同。试过 6 种方法对抗时间漂移（样本时间加权、绝对时间特征、丢弃旧数据、去季节性、连续特征分箱），AUC 提升全部小于 0.01。

**第四层：能不能用知识蒸馏？**
不能。训练了一个能看到泄露特征的教师模型（AUC≈1.0），但它的知识传不过去——学生模型的输入里根本没有那些信息。蒸馏传不了不存在的东西。

**为什么 Standard Class 是元凶？**
按运输方式拆开看：First Class 承诺 1 天、实际平均 2 天，准时率 **0%**；Second Class 承诺 2 天、实际 3.9 天；Standard Class 承诺 4 天、实际 4.0 天，准时率 **60%**。而 Standard Class 占了 60% 的数据量，它内部运输天数的波动又极大——用下单时可得的信息根本区分不了哪单会晚。

**结论：0.78 是这个数据集 + 时间切分约束下的真实天花板。** AutoGluon 跑 10 分钟自动搜索，最好也只有 0.735，比手调还低一点。

## 对抗验证的细节

训练一个分类器来判断「这条订单来自训练期还是测试期」，特征和主模型完全一样。结果这个分类器几乎完美可分——**但要注意，主要漂移来自 `Market` 这类低基数类别编码**：训练期和测试期覆盖的市场取值集合几乎不重叠，编码后造成伪漂移。真实业务漂移需要更细的口径（例如按月份看 PSI），不能只看分类器 AUC。

不管漂移来自哪里，结论是一样的：**大多数课程项目用随机切分，训练和测试分布一样，AUC 自然高；但生产环境里你永远是用过去预测未来。**

## 运行

先把数据下载到 `data/`（93MB，Kaggle 公开数据集）：

```bash
python -c "import kagglehub; kagglehub.dataset_download('evilspirit05/datasupplychain')"
```

```bash
pip install -r requirements.txt

# 复现成本分析（首次训练分位数模型约 2 分钟，之后走缓存）
python scripts/refresh_cost_analysis.py

# 参数灵敏度（换个日罚金）
python scripts/refresh_cost_analysis.py --penalty 100 --no-cache
```
